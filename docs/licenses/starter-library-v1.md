This is the immutable evidence record required by [`docs/sample-library.md` section 3.4](../sample-library.md). Every asset in the starter library manifest points at this file through its `license.evidencePath` field.

## What was acquired, and from whom

Nothing was acquired. There is no third party in this library's provenance chain.

All 200 assets are generated by `scripts/starter-library/`, which synthesizes audio from first principles — oscillators, filtered noise, modal and FM synthesis, Karplus-Strong strings, and arithmetic reverb and delay — implemented in this repository. The pipeline:

- Reads no audio file, sample, loop, or impulse response of any origin.
- Uses no third-party instrument, preset, model, or sample library, commercial or free.
- Makes no network request.
- Depends only on the Node standard library for hashing, compression, and file output.

This satisfies the second route in section 3.2: *content Solid Groove created entirely from sources it owns.*

## Why that settles the rights

Section 3.1 rejects standard royalty-free licences because Solid Groove exposes individual raw sounds in a browser, loads them into samplers, and copies or renders them during stem and Ableton export — a redistribution the usual "use in your music" grant does not cover.

Owner-created content raises none of that. Solid Groove holds the copyright in these recordings outright, so raw redistribution, sampler use, project collaboration, WAV and stem export, native project export, CDN caching, format conversion, and derivative processing are all unrestricted, in perpetuity, with no counterparty who could withdraw them.

The additional rights checks in section 3.3 are also satisfied, by construction rather than by review:

| Check | Position |
| --- | --- |
| Performer consent, personality and publicity rights | No performance and no performer. The library contains no vocals, speech, or identifiable person. |
| Composition rights | No asset is a melody, phrase, lyric, or arrangement. Tonal assets are single pitches and single chord voicings — intervals, which are not copyrightable subject matter. |
| Trademark and passing off | Asset names are descriptive. The manifest validator fails CI on a name containing third-party product branding (`909`, `Ableton`, `Amen`, and similar); see `scripts/starter-library/validate.mjs`. |
| Uploader actually created the recording | Not applicable: no upload. The generating code is in this repository's git history. |
| Contractual restrictions inherited from tools or locations | None. No third-party instrument, preset, or recording location is involved. |
| Content-ID exposure | These exact recordings did not exist before this repository generated them and appear in no released track. |
| Privacy and sensitive context | No field recording. No environment, person, or place is captured. |

## Reproducibility as evidence

Provenance for this library is stronger than a licence file, because the assets can be regenerated and checked rather than merely attested.

Each manifest entry carries `provenance.recipe` — the voice name, its exact parameters, and the seed derived from the asset ID. The generator uses a seeded PRNG and no clock or ambient randomness, so `bun run library:build` reproduces every WAV byte-for-byte, and every `files.master.sha256` in the manifest can be recomputed from source. A tampered or substituted asset does not match its content-addressed storage key.

## Intake state

These assets are at the `metadata-review` state in the [section 11](../sample-library.md) intake ladder, **not** `approved`.

Rights review and audio preparation are complete and machine-checked. What has not happened is human musical review: nobody has auditioned each asset alone and in two real project contexts against the section 11 rubric. That is deliberate — this is the testing library required by PRD `LIB-00`, and `CNT-002` promotes whatever survives review into approved factory content.

Nothing here blocks shipping the library to the alpha environment. It means the library is labelled `deliveryTier: "starter-test"` in its manifest and is not counted towards the section 6.1 approved-asset milestones.

## Takedown and revocation

There is no scenario in which this grant is withdrawn, because there is no grantor other than Solid Groove.

The delivery mechanism still supports removal: assets resolve through stable IDs and immutable content-addressed versions, so an individual asset can be moved to `deprecated` — hidden from new selection while existing project references keep resolving — without breaking a saved project.

## Scope limit

This record covers manifest `sg-starter-library` **v1 only**. A later library version that ingests recorded, commissioned, or third-party CC0 content needs its own per-asset evidence under `docs/licenses/`, and must not reuse this file.
